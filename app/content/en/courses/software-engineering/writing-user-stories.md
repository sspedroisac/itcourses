# Writing User Stories

User stories are short descriptions of functionality from the user's perspective.

They help teams focus on value instead of jumping directly into technical implementation.

---

## Common Format

A common template is:

**As a** user type, **I want** some capability, **so that** I achieve a goal.

Example:

**As a** student, **I want** to save my course progress, **so that** I can continue later.

---

## Why User Stories Help

User stories are useful because they:

- Keep the focus on user value.
- Encourage conversation.
- Support planning and prioritization.
- Break large features into smaller pieces.

They are not meant to replace all documentation.

---

## Good User Stories

A useful story is typically:

- Clear.
- Small enough to discuss and build.
- Valuable to a user or stakeholder.
- Testable when paired with acceptance criteria.

Stories that are too vague often cause confusion.

---

## Key Takeaways

- User stories express functionality from the user's point of view.
- They help teams connect technical work to real value.
- Good stories are clear, small, and meaningful.
- User stories work best when combined with discussion and acceptance criteria.
